fix+docs: Kafka 探针改轻量 TCP、预算表口径澄清、Doris Dockerfile 去多余 apt

P0 实测新增两条（都写进 HLD §8-R7 / gdd §C）：

1) Kafka healthcheck 探针过重导致「假 unhealthy」：
   原探针 kafka-broker-api-versions.sh 每次起一个 JVM，实测 **37.7 秒**，
   而 timeout 只有 10s ⇒ 永远超时（实测 FailingStreak=22），容器长期
   显示 unhealthy，但**功能完全正常**（topic/offsets/生产消费均可用）；
   还会阻断依赖 service_healthy 的 kafka-init 与 client。
   ⇒ 改用轻量 TCP 探针（实测 4.6s）：timeout 3 bash -c 'exec 3<>/dev/tcp/localhost/9092'
   改后实测 healthy / failing=0。
   教训：**探针失败 ≠ 服务失败**，先做功能探测再判断。

2) 预算表两个口径必须分清（此前我写错过一次，已纠正）：
   - scripts/config_check.py 的「常驻上限合计」按「有 mem_limit 且无 profiles」
     统计 ⇒ 默认 up 报 **5.25 GiB**（不含 profile 隔离的 Doris）
   - 「全部服务声明上限」= **10.25 GiB**（含 doris-fe 2g + doris-be 3g）
   两种场景都 < 天花板 11.68 GiB（余 6.43 / 1.43 GiB），**没有超支**。
   HLD §4.2 已改为并列两口径并说明各自含义。

Doris Dockerfile：删掉多余的 apt-get install openjdk-17 ——
   ​base-latest 实测**自带 /usr/lib/jvm/jdk-17**（java -version = 17.0.2 可用），
   直接 ENV JAVA_HOME 指过去即可，省构建时间也避开 apt 源风险。
